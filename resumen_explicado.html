Unidad 1

Algoritmos & Arreglos

Cómo se organizan los datos en memoria cuando el tamaño es fijo y conocido de antemano.

¿Qué es un algoritmo?

La idea fundamental

Antes de hablar de estructuras de datos, hay que entender qué es un algoritmo. La materia se llama "Estructura de Datos" pero en realidad estudia el binomio indisoluble datos + algoritmos: cómo guardás la información y cómo operás sobre ella.

Definición
Un algoritmo es un conjunto de instrucciones finito, no ambiguo y general que resuelve un problema. Tiene cero o más entradas y produce una o más salidas. Si la solución no existe, el algoritmo debe informarlo — no puede quedarse colgado para siempre.
Analogía
Una receta de cocina es un algoritmo. Tiene ingredientes de entrada (datos), pasos definidos y sin ambigüedad ("añadir sal al gusto" sería mala especificación), y produce un plato al final. Si falta un ingrediente clave, la receta debe avisarte — no decirte que improvises.

Etapas para resolver un problema con la computadora

La materia enfatiza que programar no es directamente sentarse a escribir código. El proceso tiene estas etapas:

Análisis — entender qué hay que resolver, definir entradas y salidas esperadas.
Diseño — escribir el algoritmo en pseudocódigo, diagramas de flujo o lenguaje natural.
Prueba de escritorio — simular a mano el algoritmo con datos de prueba para verificar que funciona.
Codificación — traducir el algoritmo a un lenguaje de programación real.
Compilación y ejecución — convertir el código a ejecutable y correrlo.
Depuración — corregir errores encontrados.
Evaluación — verificar que los resultados son correctos y el programa es eficiente.

Pseudocódigo

Es el lenguaje que usa la materia para escribir algoritmos. No es un lenguaje de programación real, es una forma de escribir lógica en español estructurado. Las instrucciones clave son:

Instrucciones básicas

Leer x — pide un valor al usuario

Escribir x — muestra un valor

x = valor — asignación

Control de flujo

Si condición entonces ... finSi

Mientras condición hacer ... finMientras

Desde i=1 hasta n ... finDesde
Terminología de Datos

¿Qué es un dato, un tipo de dato y una estructura de datos?

Estos tres conceptos se confunden mucho. Son distintos niveles de abstracción:

Dato
La unidad mínima de información. Un número, una letra, un valor lógico. Solo existe, no tiene relación con otros.
Tipo de dato
Define el conjunto de valores posibles que puede tomar una variable y las operaciones válidas sobre esos valores. Por ejemplo: el tipo "entero" abarca {…, -2, -1, 0, 1, 2, …} y permite suma, resta, multiplicación. El tipo "carácter" abarca letras y no permite suma numérica.
Estructura de datos
Una forma de organizar y relacionar varios datos en memoria para que se puedan operar eficientemente. No es solo guardar datos — es cómo se relacionan entre sí y qué operaciones tiene sentido hacer. Un arreglo es una estructura. Una lista, una pila, un árbol — también.
Analogía
Un dato es un libro individual. El tipo de dato dice qué tipo de libro es (novela, técnico, etc.). La estructura de datos es cómo organizás la biblioteca: por orden alfabético, por estante temático, o con una lista de espera. La organización determina qué tan rápido encontrás un libro.
Arreglos

¿Qué es un arreglo?

Un arreglo (array) es la estructura de datos más básica. Formalmente es un conjunto de pares (índice, valor). Informalmente: una fila de cajitas numeradas en memoria, cada una guarda un valor del mismo tipo.

Arreglo A de 6 elementos
15 3 42 8 19 7
A(1) A(2) A(3) A(4) A(5) A(6)

La característica clave de los arreglos es que son estáticos: su tamaño se define cuando se escribe el programa y no puede cambiar mientras el programa corre. Si declarás un arreglo de 100 elementos, ocupa espacio para 100 aunque solo uses 10.

Representación en memoria — ¿Cómo se guarda físicamente?

En la memoria de la computadora todo es una secuencia lineal de posiciones. Los arreglos se guardan de forma contigua — un elemento tras otro, sin saltos.

Para arreglos de una dimensión, si el arreglo empieza en la dirección α:

// dirección del elemento A(i): dirección(A(i)) = α + (i - 1) // Ejemplo: si α = 1000 y cada elemento ocupa 1 posición, // A(1) está en 1000, A(3) está en 1002, A(7) está en 1006

Para arreglos de dos dimensiones (matrices), la forma estándar es fila mayor: se guarda la fila 1 completa, luego la fila 2 completa, etc.

// Para A(1:u₁, 1:u₂) — u₁ filas, u₂ columnas // dirección de A(i, j): dirección(A(i,j)) = α + (i-1)*u₂ + (j-1) // Cantidad total de elementos: elementos = (u₁ - l₁ + 1) × (u₂ - l₂ + 1)
Para el examen
Si te preguntan cuántos elementos tiene A(2:5, 1:4): filas = (5-2+1) = 4, columnas = (4-1+1) = 4, total = 16 elementos.
Listas Ordenadas

¿Qué es una lista ordenada?

Una lista ordenada es una secuencia (a₁, a₂, ..., aₙ) donde la única relación entre los elementos es la precedencia: cada elemento sabe quién está antes y quién está después. No hay otro criterio de organización implícito (aunque se puede ordenar por valor).

Se implementa en un arreglo donde el orden importa. Las operaciones posibles son: recorrer, buscar, insertar, borrar, ordenar, mezclar.

Insertar manteniendo el orden

Este es el algoritmo más pedido en la unidad. El problema es: tenés una lista ya ordenada de n elementos en un arreglo, y querés agregar el elemento x en la posición correcta, desplazando los elementos mayores para hacer lugar.

Analogía
Tenés una fila de cartas ordenadas boca abajo sobre la mesa. Sacás una carta nueva y la querés poner en su lugar. ¿Qué hacés? Empezás por el final de la fila, y vas corriendo cada carta hacia adelante mientras sean más grandes que la tuya. Cuando encontrás una más chica (o llegaste al principio), ponés tu carta ahí.
// PROC AGREGAR(L, x) — inserta x en lista L de n elementos manteniendo orden i = n + 1 // empezamos desde la posición siguiente al último Mientras i > 1 y L(i-1) > x hacer L(i) = L(i-1) // corremos el elemento una posición hacia adelante i = i - 1 // retrocedemos finMientras L(i) = x // insertamos x en el hueco que quedó

Ejemplo: Lista = [1, 3, 7, 9], queremos insertar 5.

  • i=5: L(4)=9 > 5 → L(5)=9, i=4
  • i=4: L(3)=7 > 5 → L(4)=7, i=3
  • i=3: L(2)=3 < 5 → salimos del while
  • L(3) = 5 → Lista queda = [1, 3, 5, 7, 9] ✓
Suma de Polinomios con Arreglos

¿Por qué representar polinomios en un arreglo?

Un polinomio como P(x) = 3x⁵ - 2x² + 7 tiene términos con coeficiente y exponente. Si lo guardamos de forma naive necesitaríamos guardar el coeficiente de cada exponente posible — para P(x) = x¹⁰⁰⁰ + 1 necesitaríamos 1001 posiciones aunque solo 2 sean distintas de cero.

La solución: guardar solo los términos no nulos en el formato:

Formato del polinomio
(m, eₘ, bₘ, eₘ₋₁, bₘ₋₁, ..., e₁, b₁, e₀, b₀)

Donde: m = cantidad de términos con coeficiente ≠ 0, eᵢ = exponente del término i, bᵢ = coeficiente del término i. Los exponentes van en orden decreciente.

Ejemplo: P(x) = x⁴ - 10x³ + 3x² + 1

Representación en arreglo
4 4 1 3 -10 2 3 0 1
m=4 exp coef exp coef exp coef exp coef

Algoritmo SUMPOL — Lógica explicada

Tenemos dos polinomios A y B guardados así, y queremos sumarlos para obtener C. Usamos punteros p (recorre A) y q (recorre B), comenzando en la posición 2 (saltamos el m inicial).

Comparamos los exponentes actuales de A y B. Hay tres casos posibles:

Caso 1: A(p) = B(q) — exponentes iguales

Sumamos los coeficientes. Si la suma da 0, no se agrega al resultado (término nulo). Si es distinto de cero, se agrega con ese exponente. Avanzamos p y q.

Caso 2: A(p) > B(q) — exp de A es mayor

El término de A va primero en C (va de mayor a menor exponente). Copiamos el término de A a C. Avanzamos solo p.

Caso 3: A(p) < B(q) — exp de B es mayor

El término de B va primero. Copiamos el término de B a C. Avanzamos solo q. Al terminar el bucle, copiamos los términos restantes del que sobró.
Matrices Sparse (Ralas)

¿Qué es una matriz sparse?

Es una matriz donde la gran mayoría de sus elementos son cero. Si tenés una matriz de 100×100 = 10.000 elementos pero solo 50 son distintos de cero, guardarla completa sería un enorme desperdicio de memoria.

Analogía
Imaginá un estadio de fútbol con 50.000 asientos. Si en un entrenamiento solo van 40 personas, sería ridículo llevar un registro de todos los asientos vacíos. Mucho mejor llevar una lista de las 40 personas presentes anotando en qué fila y asiento está cada una.

Representación compacta como lista de 3-uplas

En vez de guardar toda la matriz, guardamos solo los elementos distintos de cero como tuplas (fila, columna, valor), en una nueva matriz M donde:

  • M(0, 1) = cantidad de filas de la matriz original
  • M(0, 2) = cantidad de columnas de la matriz original
  • M(0, 3) = cantidad de elementos distintos de cero
  • M(k, 1..3) = fila, columna, valor del k-ésimo elemento no nulo

Las tuplas se guardan ordenadas por fila, y dentro de cada fila por columna.

Importante
La transpuesta de una matriz sparse se obtiene intercambiando columna y fila en cada 3-upla y reordenando. Esto puede caer en el examen.
Unidad 2

Pilas y Colas

Estructuras lineales donde el orden de entrada y salida de los datos está controlado.

La idea detrás de pilas y colas

¿Por qué no usar siempre arreglos directos?

Los arreglos te dan acceso a cualquier posición. Pero hay problemas donde el orden de acceso importa y querés restringirlo para reflejar la realidad del problema. Ahí entran Pilas y Colas: son arreglos con reglas de acceso muy específicas.

Pila — LIFO

Last In, First Out
El último en entrar es el primero en salir. Como una pila de platos: siempre sacás del tope.

Cola — FIFO

First In, First Out
El primero en entrar es el primero en salir. Como la fila del banco: el que llegó primero es el primero en ser atendido.
PILA (Stack)

Concepto y variables

Una pila es una colección de datos accesible solo por un extremo, llamado tope. Podés agregar (push) y sacar (pop) únicamente desde el tope. El resto de los elementos están "tapados" y son inaccesibles hasta que sacás los de arriba.

Analogía
Una pila de bandejas en un buffet. Siempre agarrás la bandeja de arriba. Siempre devolvés la bandeja sobre la pila. Si querés la bandeja del fondo, tenés que sacar todas las de arriba primero.

Para implementar una pila en un arreglo necesitás:

  • S(1:n) — el arreglo que guarda los elementos
  • n — capacidad máxima de la pila
  • tope — índice del último elemento insertado. Empieza en 0 (pila vacía). Si tope = n, está llena.
Estado de la pila después de agregar A, B, C
tope → C S(3) ← último en entrar, primero en salir
B S(2)
A S(1) ← primero en entrar, último en salir

Procedimiento AGREGAR (Push)

Antes de agregar, verificamos que la pila no esté llena. Si hay lugar, subimos el tope y ponemos el elemento.

PROC AGREGAR(x, S, n, tope) si tope = n entonces // está llena — no podemos agregar más llamar LLENA retornar finSi tope = tope + 1 // subimos el tope S(tope) = x // guardamos el elemento en la nueva posición finProc

Procedimiento ELIMINAR (Pop)

Antes de eliminar, verificamos que la pila no esté vacía. Si tiene elementos, tomamos el del tope y bajamos el tope.

PROC ELIMINAR(x, S, tope) si tope <= 0 entonces // está vacía — no hay nada para sacar llamar VACIA retornar finSi x = S(tope) // guardamos el elemento en x para devolverlo tope = tope - 1 // bajamos el tope (el elemento "ya no está") finProc
Errores clásicos
Overflow (desbordamiento): intentar agregar cuando tope = n. Underflow: intentar sacar cuando tope = 0. Ambos llaman a sus procedimientos de error respectivos.

¿Para qué sirven las pilas en la práctica?

  • Llamadas a funciones/subprogramas: cuando llamás a una función, el estado actual del programa (variables, dirección de retorno) se guarda en una pila. Al terminar la función, se recupera ese estado y el programa sigue desde donde estaba.
  • Recursividad: cada llamada recursiva apila su estado. Cuando se llega al caso base, se desapila de vuelta.
  • Evaluación de expresiones aritméticas: para convertir y evaluar expresiones matemáticas (tema que veremos pronto).
COLA (Queue)

Concepto y variables

Una cola es una estructura donde los elementos entran por un extremo (REAR / final) y salen por el otro (FRONT / frente). Es exactamente como la fila del supermercado.

Analogía
La fila de atención al cliente. Llegás y te ponés al final (rear). El que es atendido es el que está al frente (front). Nadie puede "colarse" en el medio.

Variables necesarias:

  • q(1:n) — arreglo que guarda los elementos
  • front — índice del primer elemento (el próximo a salir). Inicialmente = 0.
  • rear — índice del último elemento (el último en entrar). Inicialmente = 0.
  • Cola vacía: front = rear
PROC AGREGAR(x, q, n, rear) si rear = n entonces // no hay espacio al final llamar LLENA retornar finSi rear = rear + 1 q(rear) = x finProc PROC ELIMINAR(x, q, n, front, rear) si front = rear entonces // vacía llamar VACIA retornar finSi front = front + 1 x = q(front) finProc

El problema de la cola simple en arreglo

Hay un problema grave con esta implementación: cuando sacás elementos, front avanza pero ese espacio jamás se reutiliza. Si agregás y sacás muchos elementos, rear llega al final del arreglo y el sistema dice "está lleno" aunque haya montones de espacios libres al principio.

La cola "llena" aunque hay espacio libre al inicio
vacío vacío X Y Z
espacios libres inutilizables front=3 rear=5=n → "LLENA"

Solución: Cola Circular

La idea es tratar el arreglo como si fuera un círculo: cuando llegás al final, el siguiente lugar es el principio. Esto se logra con la operación módulo (mod).

Con una cola circular de n posiciones, la capacidad real es n-1 (se deja una posición libre para poder distinguir entre cola llena y cola vacía).

PROC AGREGAR CIRCULAR(x, Q, n, front, rear) rear = (rear + 1) mod n // avanzamos rear con módulo (da la vuelta) si front = rear entonces // si después de avanzar rear alcanza a front → llena llamar LLENA retornar finSi Q(rear) = x finProc PROC ELIMINAR CIRCULAR(x, Q, n, front, rear) si front = rear entonces // vacía llamar VACIA retornar finSi front = (front + 1) mod n x = Q(front) finProc
Cómo funciona el mod
Si n=6 y rear=5, (5+1) mod 6 = 0. Si rear=0, (0+1) mod 6 = 1. Así el índice "da la vuelta" al llegar al final del arreglo. El rango válido es 0 a n-1.
Evaluación de Expresiones Aritméticas

¿Por qué existe la notación postfija?

Cuando vos escribís 3 + 4 × 2, sabés que hay que hacer primero la multiplicación por las reglas de precedencia. Pero una computadora procesa de izquierda a derecha sin "visión hacia adelante". La notación postfija (también llamada notación sufija o polaca inversa) reordena los operadores para que una computadora pueda evaluar la expresión de izquierda a derecha sin necesitar precedencia ni paréntesis.

Infija (como la escribimos nosotros)

El operador va ENTRE los operandos.
A + B × C Necesita reglas de precedencia para evaluarse.

Postfija (como la procesa la PC)

El operador va DESPUÉS de sus operandos.
A B C × + Se evalúa siempre de izquierda a derecha.

Tabla de Prioridades — ¡Esta hay que sabérsela!

Para convertir de infija a postfija, usamos una pila y una tabla que asigna dos prioridades a cada operador: PP (Prioridad en Pila) y PE (Prioridad en Expresión).

SímboloPP (en pila)PE (en expresión)¿Por qué?
fin (∅)-1-1Nunca desplaza nada, siempre para el proceso
^ (potencia)34PE > PP → un nuevo ^ no es desplazado por el ^ en pila (asocia a derecha)
* /22Prioridad media, asocia a izquierda
+ -11Prioridad baja, asocia a izquierda
(04En pila nunca desplaza nada. En expresión frena todo.
)——No va a la pila. Provoca vaciado hasta encontrar (

PROC.POSFIJO — Reglas paso a paso

Se inicializa la pila con el símbolo ∅ (fin) en la posición 1. Luego se lee token por token de la expresión:

Si el token es un operando (A, B, x, 3, etc.) → se imprime directamente. Los operandos nunca van a la pila.
Si el token es ")" → se saca e imprime todo de la pila hasta encontrar "(" — el paréntesis de apertura se descarta sin imprimir.
Si el token es fin (∅) → se vacía toda la pila imprimiendo todo lo que queda.
Si el token es un operador (+, -, *, /, ^) → mientras PP del tope de la pila ≥ PE del operador entrante, sacar e imprimir el tope. Luego meter el nuevo operador en la pila.
La llave del algoritmo
La comparación PP(tope) ≥ PE(nuevo) determina si el operador en pila "tiene más o igual derecho" de salir antes que el nuevo. Si sí, sale. Si no, el nuevo entra. Esto implementa la precedencia automáticamente.

Ejemplo completo: A / B ^ C + D * E - A * C

// Resultado postfijo paso a paso: Token: A → imprime A Salida: A Token: / → PP(∅)=-1 < PE(/)=2 → apila Pila: [∅, /] Token: B → imprime B Salida: A B Token: ^ → PP(/)=2 < PE(^)=4 → apila Pila: [∅, /, ^] Token: C → imprime C Salida: A B C Token: + → PP(^)=3 ≥ PE(+)=1 → saca ^ Salida: A B C ^ → PP(/)=2 ≥ PE(+)=1 → saca / Salida: A B C ^ / → PP(∅)=-1 < PE(+)=1 → apila Pila: [∅, +] Token: D → imprime D Salida: A B C ^ / D Token: * → PP(+)=1 < PE(*)=2 → apila Pila: [∅, +, *] Token: E → imprime E Salida: A B C ^ / D E Token: - → PP(*)=2 ≥ PE(-)=1 → saca * Salida: A B C ^ / D E * → PP(+)=1 ≥ PE(-)=1 → saca + Salida: A B C ^ / D E * + → PP(∅)=-1 < PE(-)=1 → apila Pila: [∅, -] Token: A → imprime A Salida: A B C ^ / D E * + A Token: * → PP(-)=1 < PE(*)=2 → apila Pila: [∅, -, *] Token: C → imprime C Salida: A B C ^ / D E * + A C Token: ∅ → vaciamos todo la pila Salida: A B C ^ / D E * + A C * -

PROC.EVAL — Evaluar expresión postfija

Una vez en postfijo, evaluar es simple. Se recorre la expresión y:

  • Si es operando → se apila
  • Si es operador → se sacan los 2 últimos operandos de la pila, se opera, y el resultado se apila
  • Cuando llega el fin, el único elemento en la pila es el resultado
PROC EVAL(E) tope = 0 Repetir x = NEXT-TOKEN(E) si x = fin: retornar S(tope) // resultado final si x = operando: AGREGAR(x, S, n, tope) sino: b = S(tope), tope-- // segundo operando a = S(tope), tope-- // primer operando resultado = a op b // aplicar operador x AGREGAR(resultado, S, n, tope) finRepetir finProc
Unidad 3

Listas Encadenadas

Estructuras dinámicas donde los datos pueden estar en cualquier lugar de la memoria, conectados mediante punteros.

El problema con los arreglos

¿Por qué necesitamos algo distinto?

Los arreglos son cómodos pero tienen un problema fundamental: son estáticos. Antes de usarlos, hay que decirle a la computadora cuánto espacio reservar. Si pedís poco, te quedás sin lugar. Si pedís mucho, desperdiciás memoria.

Además, insertar o borrar un elemento en el medio de un arreglo requiere desplazar todos los elementos de alrededor — una operación costosa.

Analogía
Imaginá que tenés que poner sillas en una fila para un evento. Con un arreglo, ponés exactamente N sillas pegadas una a la otra. Si viene una persona más, no hay lugar. Si vienen menos, sobran sillas vacías ocupando espacio.

Con una lista encadenada, cada persona tiene su silla en cualquier parte del salón, y le decís "cuando termines, pasale la palabra a fulano que está en la esquina". Podés agregar o sacar personas sin mover a nadie más.
Estructura dinámica
Una estructura dinámica puede crecer y decrecer en tiempo de ejecución. No reserva un bloque fijo de memoria: toma memoria cuando la necesita y la devuelve cuando no. Los elementos pueden estar en posiciones de memoria no contiguas, conectados entre sí mediante punteros.
Lista Simple Encadenada (LSE)

¿Qué es un nodo?

La unidad básica de una lista encadenada es el nodo. Cada nodo contiene al menos dos cosas: el dato que queremos guardar, y un puntero que indica la dirección del siguiente nodo en la lista.

Estructura de un nodo
DATO PUNTERO →

El puntero del último nodo vale 0 (indica que no hay siguiente). La variable LIST contiene la dirección del primer nodo. Si LIST = 0, la lista está vacía.

Lista: Diaz → Heredia → Martinez → Paz (fin)
LIST=3  →  [Diaz | 7]  →  [Heredia | 1]  →  [Martinez | 5]  →  [Paz | 0]
Los números son direcciones de memoria (no son secuenciales — pueden estar en cualquier posición)

GETNODE y RET — las operaciones de memoria

Para manejar memoria dinámica, la materia usa dos operaciones abstractas:

GETNODE(X)

"Dame un nodo libre." Devuelve en X la dirección de un nodo disponible en el espacio libre. Si no hay nodos libres, error. Equivale a un malloc en C.

RET(X)

"Devolvé este nodo." Libera el nodo en la dirección X, devolviéndolo al espacio disponible. Equivale a un free en C.

El Espacio Disponible (DISPO)

Los nodos libres no desaparecen — se guardan encadenados en una lista especial llamada espacio disponible, accedida por el puntero DISPO. Esta lista funciona como una pila: GETNODE saca el primer nodo disponible, RET devuelve un nodo al principio.

// Inicializar el espacio disponible con n nodos PROC INICIALIZAR(n) desde i = 1 hasta n-1 P(i) = i + 1 // cada nodo apunta al siguiente finDesde P(n) = 0 // el último apunta a nada DISPO = 1 // DISPO apunta al primero libre finProc

Crear una lista encadenada

// Crear lista con dos nodos "MAT" y "PAT". T apunta al inicio. PROC CREAR(T) llamar GETNODE(X) T = X DATO(X) = "MAT" P(X) = 0 // por ahora es el único nodo llamar GETNODE(X) // pedimos otro nodo P(T) = X // el primer nodo apunta al nuevo DATO(X) = "PAT" P(X) = 0 // "PAT" es el último finProc

Agregar un nodo después del nodo X

Para insertar entre dos nodos, solo hay que cambiar punteros. No se mueve ningún otro elemento.

PROC AGREGAR(T, X) llamar GETNODE(I) // pedimos un nodo nuevo DATO(I) = nuevoDato si T = 0 entonces // lista vacía: el nuevo es el único T = I P(T) = 0 sino P(I) = P(X) // el nuevo apunta a quien seguía a X P(X) = I // X ahora apunta al nuevo finSi finProc

Eliminar el nodo X (Y = nodo anterior a X)

Para eliminar, simplemente "saltamos" el nodo X haciendo que el anterior apunte al siguiente. Luego devolvemos X a DISPO.

PROC ELIMINAR(T, X, Y) // Y = 0 significa que X es el primer nodo si Y = 0 entonces T = P(T) // el inicio de la lista es ahora el segundo nodo sino P(Y) = P(X) // el anterior de X ahora apunta al siguiente de X finSi llamar RET(X) // devolvemos el nodo al espacio disponible finProc

Agregar manteniendo orden

Recorremos la lista con dos punteros: p (nodo actual) y q (nodo anterior). Avanzamos mientras el dato del nodo actual sea menor que el nuevo dato. Insertamos entre q y p.

Pilas y Colas sobre LSE

¿Para qué representarlas como listas encadenadas?

Ventaja principal: no tienen límite fijo de tamaño. Una pila en arreglo tiene capacidad n y tira overflow si querés meter más. Una pila encadenada solo está limitada por la memoria disponible del sistema.

Pila Encadenada — AGREGAR

llamar GETNODE(y) DATO(y) = x P(y) = tope // apunta al anterior tope tope = y // el nuevo es el tope

Pila Encadenada — ELIMINAR

si tope = 0: ERROR, retornar x = DATO(tope) y = tope tope = P(tope) // tope baja llamar RET(y)

Cola Encadenada — AGREGAR (R=rear, F=front)

llamar GETNODE(y) DATO(y) = x, P(y) = 0 si F = 0 entonces // cola vacía F = R = y sino P(R) = y R = y

Cola Encadenada — ELIMINAR

si F = 0: ERROR, retornar y = F F = P(y) x = DATO(y) llamar RET(y)
Listas Circulares

¿Qué las hace circulares?

En una lista circular, el último nodo no apunta a 0 sino que apunta de vuelta al primer nodo (o al nodo cabecera). Esto forma un "anillo" cerrado sin principio ni fin.

Analogía
Una cadena circular de personas tomadas de la mano. No hay un primero ni un último — podés recorrerla indefinidamente en cualquier dirección partiendo desde cualquier punto.

Nodo Cabecera

En listas circulares se usa un nodo cabecera: un nodo ficticio que siempre está presente aunque la lista esté "vacía". Su campo de dato generalmente se marca con un símbolo especial (*).

Ventaja: la lista nunca queda sin nodos, lo que simplifica los algoritmos de inserción y borrado (no hay que tratar el caso especial de lista vacía).

Condición de lista circular vacía
La lista tiene solo el nodo cabecera, que apunta a sí mismo: T = P(T). En una LSE simple, vacía significa LIST = 0.
Lista Doble Encadenada (LDE)

¿Para qué dos punteros?

En una LSE, para borrar el nodo X necesitás el nodo anterior (Y) — porque si no sabés quién apunta a X, no podés cambiar ese puntero. Esto requiere siempre recorrer desde el principio o mantener un puntero auxiliar.

La LDE resuelve esto dando a cada nodo dos punteros: uno al siguiente (PS) y uno al anterior (PA). Desde cualquier nodo podés ir en ambas direcciones.

Nodo de LDE
← PA DATO PS →
Propiedad fundamental
PS(PA(x)) = x y PA(PS(x)) = x — si avanzás y después retrocedés (o viceversa), volvés al mismo nodo. Esto verifica que los punteros son consistentes.

LDE Circular con Nodo Cabecera

Es la forma más común en la práctica. Combina las ventajas de circular (nunca vacía del todo) con las de doble (navegación en ambos sentidos). La lista vacía tiene solo la cabecera, con PS y PA apuntando a sí misma.

AGREGAR después del nodo X

PROC AGREG-1(X, P, L) si L = 0 entonces // lista vacía PA(p) = PS(p) = 0 L = p sino PA(p) = x // el nuevo apunta atrás a X PS(p) = PS(x) // el nuevo apunta adelante al que seguía a X PS(x) = p // X ahora apunta al nuevo PA(PS(p)) = p // el que seguía ahora apunta atrás al nuevo finSi finProc

ELIMINAR nodo X

PROC ELIMINAR(L, X) si x = L entonces // era el único nodo L = 0 sino si PS(x) ≠ 0 entonces PA(PS(x)) = PA(x) // el siguiente de X ahora apunta atrás al anterior de X finSi PS(PA(x)) = PS(x) // el anterior de X ahora apunta adelante al siguiente de X finSi llamar RET(X) finProc
Listas Generalizadas

¿Qué es una lista generalizada?

Una lista generalizada es una lista donde los elementos pueden ser átomos (valores simples, como un número o letra) o sublistas (otras listas). Es una estructura recursiva: una lista puede contener otras listas que a su vez contienen otras listas.

Ejemplo
M = (a, (b, c), (d, e), f)

M tiene 4 elementos: el átomo a, la sublista (b,c), la sublista (d,e), y el átomo f.

Propiedades de una lista generalizada

  • Longitud: cantidad de elementos directos en el nivel principal (independientemente de si son átomos o sublistas). Para M de arriba, longitud = 4.
  • Profundidad: máximo nivel de anidamiento. La lista principal tiene nivel 1. Cada sublista que convoca tiene nivel = nivel del padre + 1. La profundidad es el nivel máximo alcanzado. Para M: profundidad = 2.
  • Contador de referencia: cuántas otras listas apuntan a esta lista (relevante cuando varias listas comparten una misma sublista).

Estructura del nodo generalizado

Cada nodo tiene tres campos: TAG, DATO/DIR, y PUNTERO.

TAG = 0 → Átomo

[TAG=0 | DATO | PUNTERO]
DATO contiene el valor del átomo. PUNTERO apunta al siguiente elemento de la lista padre.

TAG = 1 → Sublista

[TAG=1 | DIR_CABECERA | PUNTERO]
DATO contiene la dirección de la cabecera de la sublista. PUNTERO apunta al siguiente elemento de la lista padre.
Importante — Contador de referencia
Si dos listas apuntan a la misma sublista, y borrás una de ellas, la sublista no debe liberarse porque la otra lista todavía la necesita. El contador de referencia dice cuántas listas apuntan a esta. Solo se libera cuando ese contador llega a 0.

Comparativa de estructuras

¿Cuándo usar cada estructura?

Las confusiones más comunes

Confusión 1 — Pila vs Cola
En la Pila: entrar y salir por el mismo extremo (el tope). En la Cola: entrar por un extremo (rear) y salir por el opuesto (front). La variable tope es exclusiva de la pila. Las variables front y rear son exclusivas de la cola.
Confusión 2 — Cola simple vs Cola circular
En la cola simple, front y rear solo avanzan hacia adelante. El espacio liberado al sacar elementos nunca se reutiliza. En la cola circular, se usa mod n para que los punteros "den la vuelta". La condición de vacía es siempre front = rear. La de llena en circular es (rear+1) mod n = front.
Confusión 3 — LSE vacía vs Lista Circular vacía
LSE vacía: LIST = 0. Lista circular vacía con cabecera: T = P(T) — la cabecera apunta a sí misma. La diferencia es que la circular nunca queda "sin nodos" porque siempre tiene la cabecera.
Confusión 4 — Estática vs Dinámica
Estática = arreglo = tamaño fijo = posiciones contiguas en memoria = se define al escribir el programa. Dinámica = lista encadenada = crece/decrece en ejecución = posiciones NO contiguas = se conecta con punteros. Las pilas y colas pueden implementarse de ambas formas — la diferencia es si usás arreglo o lista como base.
Para repasar rápido
  • Arreglo: (índice, valor). Dirección = α + (i-1). Estático.
  • Pila: LIFO. Variable: tope. Llena: tope=n. Vacía: tope=0.
  • Cola: FIFO. Variables: front, rear. Vacía: front=rear. Circular usa mod n.
  • Expresiones: tabla PP/PE. Operando → imprime. Operador → compara PP/PE. ")" → vacía hasta "(". Fin → vacía todo.
  • LSE: nodo = [DATO | PUNTERO]. LIST apunta al primero. DISPO maneja nodos libres. GETNODE pide, RET devuelve.
  • LDE: nodo = [PA | DATO | PS]. Permite ir en ambas direcciones. PS(PA(x)) = x.
  • Circular vacía: T = P(T). Circular tiene nodo cabecera siempre.
  • Lista generalizada: TAG=0 átomo, TAG=1 sublista. Longitud = elementos directos. Profundidad = nivel máximo.
